# Model Card — MediStock AI demand forecaster

Following the spirit of Mitchell et al. (2019) model cards: what this model is for, how it
was built, where it fails, and what it must not be used for.

---

## Model details

| Field | Value |
|---|---|
| Model type | `HistGradientBoostingRegressor` inside a scikit-learn `Pipeline` |
| Task | Regression: total units demanded per product over the next 30 days |
| Input | 29 features from 180 days of demand history + static product attributes + origin calendar |
| Output | Point forecast (units), plus a residual-quantile interval |
| Artifact | `artifacts/v1/model.joblib` (SHA-256 verified by `ArtifactStore`) |
| Contract version | 1.0.0 |
| Prediction origin | 2025-10-01 (fixed in this artifact) |
| Horizon | 30 days |
| Training date | see `artifacts/v1/manifest.json` → `created_at_utc` |
| Library versions | see manifest → `library_versions` |

Hyperparameters (selected on validation):
`learning_rate=0.06, max_leaf_nodes=15, max_iter=400, min_samples_leaf=15,
l2_regularization=0.0`. Candidate grid and the losing configurations are recorded in
`training_config.json` and `metrics.json` → `tuning`.

## Intended use

* Inventory decision support for a **single retail pharmacy**.
* Answering: "how many units of product X should we expect to sell in the next month, and
  which batches will not clear before expiry?"
* Generating human-reviewable replenishment and rotation suggestions.

## Out-of-scope / prohibited use

* **Not medical advice.** No dosage, diagnosis, treatment or substitution guidance.
* **Not autonomous procurement.** The model must never be wired to an ordering system.
* **Not for patient-level demand.** No patient data exists in this system.
* **Not for a different horizon.** The artifact is locked to 30 days and returns
  `422 invalid_request` for anything else.
* **Not for a different date.** The bundle holds history up to one origin; arbitrary
  origins are rejected rather than answered with a stale prediction.
* **Not for a different pharmacy's data** without retraining and revalidation.

## Training data

Synthetic, generated by `ml/data_generation/` with seed 42. 120 products × 610 days,
67,558 transactions, 298 batches. Snapshot date 2025-10-01.

**This is the single most important caveat**: the model is evaluated on data produced by a
generator whose structure the feature set can largely represent. Its measured accuracy is
an upper bound on real-world performance, not an estimate of it.

## Evaluation

Chronological split; test scored once after selection.

| Metric (test) | Value |
|---|---:|
| MAE | 29.66 units |
| RMSE | 39.96 units |
| WAPE | 0.108 |
| Bias | +4.72 units (slight over-forecast) |
| Seasonal-naive baseline WAPE | 0.132 |
| Relative improvement over baseline | 18% |

Rolling-origin mean WAPE across three pre-test folds: 0.118 (RF 0.126, naive 0.136,
MA90 0.190).

## Fairness and subgroup behaviour

Not a protected-attribute model — no demographic variables exist. The meaningful subgroups
are product categories and demand sparsity:

* **Sparse products (>25% zero-demand days): WAPE 0.255 vs 0.099 for dense products.**
  The serving layer attaches a low-confidence note for these rather than implying
  uniform precision.
* **Seasonal categories are the weakest**: antihistamines bias +34.4 units, antibiotics
  +13.9 — both under-react at the shoulder of a sharp seasonal peak.

## Limitations

1. Synthetic data; no stockout censoring; no promotion or competitor signal in features.
2. Single fixed origin; no online updating.
3. Aggregated 30-day target; no within-horizon timing (this feeds a documented assumption
   in the expiry-risk extrapolation).
4. Tree models cannot extrapolate beyond the demand range seen in training: a genuine surge
   above the historical maximum will be under-forecast.
5. Prediction interval is empirical residual quantiles, not calibrated per product.

## Ethical considerations

Explicitly advisory; every response carries a disclaimer; synthetic provenance is exposed
via the API and dashboard; no personal data is processed; the pharmacist retains
accountability for every action taken from the output.

## Maintenance

Retraining is a documented, seeded, reproducible pipeline. A retrain rewrites the artifact
bundle and the manifest, which invalidates cached service containers automatically (keyed
by artifact version). There is no automatic drift detection — see `LIMITATIONS.md` and the
"before commercial deployment" list in the technical report.
